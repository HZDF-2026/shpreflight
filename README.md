# shpreflight

**Check an agent-written shell command before it burns a turn failing.**

shpreflight is a pre-flight diagnostic for shell commands generated by AI
agents. It lexes the command, checks it against the shell it will actually
run in, scans for destructive patterns, and resolves every command head
against PATH — all before the command executes, in about a tenth of a
millisecond.

```console
$ shpreflight check "echo done && exit 0" --shell powershell5
shpreflight: fail (1 error(s), 0 warning(s)) for powershell5
  SEP-AND [error] syntax: operator '&&' is not supported in this shell
    fix: separate commands, or chain with ';' if order alone matters

$ shpreflight check "curl -sL https://install.example.sh | sh" --shell bash
shpreflight: fail (1 error(s), 0 warning(s)) for bash
  PIPE-EXEC [error] danger: pipe feeds untrusted input into 'sh' — remote-code-execution pattern (curl ... | sh)
    fix: download first, inspect, then run
```

## Why this exists

The three failure classes that eat the most agent turns are all checkable
*before* execution — and none of them is visible in the command text
itself:

| Failure class | Evidence |
|---|---|
| **command not found** | The largest single category in the Terminal-Bench 2.0 agent benchmark: 24.1% of all sampled command failures were executables not installed or not on PATH — the next category (failure running the executable) sits at 9.6% ([arXiv:2601.11868](https://arxiv.org/abs/2601.11868), Fig. 9). |
| **dialect mismatch** | `&&` and `||` pipeline chain operators only exist in PowerShell 7+ ([What's new in PowerShell 7.0](https://learn.microsoft.com/powershell/scripting/whats-new/what-s-new-in-powershell-70)); the Windows default `powershell.exe` is 5.1. Agents trained on bash emit them on every chain. |
| **destructive operations** | `curl … | sh`, `rm -rf`, force-push, `dd of=/dev/...`: irreversible, and no exit code ever tells you it was a bad idea. |

Existing tooling checks these *after* the damage: linters for humans
(shellcheck), sandboxes for execution time, retries for everything. The
gap shpreflight fills is the agent's pre-execution decision point: run
this, or fix it first?

## What it checks

| Family | Sample codes | Catches |
|---|---|---|
| dialect (14 rules) | `SEP-AND` `SEP-OR` `REDIR-DEVNULL` `ENV-VAR` `BRACE-VAR` `SPECIAL-VAR` `EXPORT` `SOURCE` `BACKTICK` `CURL-ALIAS` `RM-FLAGS` `CMDLET-IN-POSIX` `POSIX-CMD` `UNCLOSED-QUOTE` | commands that parse in one shell and die (or quietly do something else) in another |
| danger (14 patterns) | `RM-ROOT` `PIPE-EXEC` `GIT-RESET-HARD` `GIT-PUSH-FORCE` `DD-RAW` `FORMAT` `SHUTDOWN` `CHMOD-777-ROOT` `REDIR-SENSITIVE` … | destructive operations before they run |
| tools | `TOOL-NOT-FOUND` | the #1 agent failure mode, pre-checked in milliseconds |

The dialect rules are deliberately two-directional: bash-isms aimed at
PowerShell (`&&`, `$VAR`, `/dev/null`, backticks) and PowerShell-isms aimed
at POSIX shells (`Remove-Item`, `Select-String`). Rules fire only for
shells where they genuinely break — `&&` on pwsh7 is fine, on 5.1 it is not.

## Built for agents

- **JSON output** (`--format json`) with stable issue codes, severity,
  kind, human-readable message, and a `fix` hint an agent can act on.
- **Machine-readable exit codes**: 0 ok, 1 warn, 2 fail, 3 usage error.
- **Cheap enough to call before every command**: a warm check costs
  ~0.06 ms in-process; a cold CLI invocation ~100 ms on Windows (the test
  suite asserts warm < 10 ms and CLI < 500 ms).
- **Zero dependencies** — Python 3.9+ stdlib only. PATH resolution is a
  single directory scan, cached per process.
- **Python API**: `preflight(cmd, target="bash")` returns a `Report`.

```console
$ shpreflight check "rm -rf /tmp/cache" --shell bash --no-path-check --format json
{
  "command": "rm -rf /tmp/cache",
  "target": "bash",
  "verdict": "warn",
  "errors": 0,
  "warnings": 1,
  "issues": [
    {
      "code": "RM-RECURSIVE",
      "severity": "warning",
      "kind": "danger",
      "message": "rm: recursive delete — irreversible without a trash can",
      "fix": "list the target first, or use a git-tracked directory"
    }
  ],
  "tools": [],
  "elapsed_ms": 0.04
}
```

## Install

```console
pip install .
```

Or run from a checkout: `python -m shpreflight check "ls -la"`.

Ports: the same checker ships as a Go binary (`cmd/shpreflight`,
`scripts/build_matrix.py` cross-compiles 9 OS/arch targets), a C99
single file (`c/`), a C++17 single file (`cpp/`), and a Rust crate
(`rs/`). All six implementations share one danger table, generated from
`shpreflight/danger.py` by `proofs/export_patterns.py` into
Lean/Go/C/C++/Rust sources — regenerate after any table edit so no port
drifts.

## Usage

```
shpreflight check "git status && git diff" [--shell SHELL]
                 [--format text|json] [--no-path-check] | --stdin
shpreflight shells          # list supported shell dialects
```

- `--shell`: `auto` (default, by platform: powershell5 on Windows, bash
  elsewhere), `powershell5`, `pwsh7`, `bash`, `cmd`, `sh`.
- `--stdin`: read the command from stdin instead of argv (avoids host
  shell quoting issues).
- `--no-path-check`: skip PATH resolution (pure static checks).

## Formal verification

Two things make a pre-flight checker trustworthy: it must not lose
characters while lexing (a destructive fragment could hide in a lexing
blind spot), and its danger table must not rot (a pattern that can never
match again fails silently forever). Both are machine-checked in
plain Lean 4 core — no Mathlib, seconds to build:

| Theorem | Guarantees |
|---|---|
| `reconstruct_lexer` | concatenating all token texts reproduces the input string character for character — the lexer conserves every character |
| `all_patterns_alive` | every entry in the danger table is matched by a concrete witness command — no dead entries |
| `patternCodes_nodup` | issue codes in the table are unique, so consumers can key on them |

The danger table is *exported verbatim from the Python implementation*
(`proofs/export_patterns.py` → `proofs/Patterns.lean`), so the proofs
cannot drift from the code that ships. Re-verification is one command:

```console
powershell -ExecutionPolicy Bypass -File proofs\verify_proofs.ps1
```

The script re-exports the table from the live Python code, compiles both
proof files, greps for `sorry`/`admit`, and audits proof axioms
(`#print axioms` — no `sorryAx`). Override the toolchain with
`$env:LEAN_BIN`. Axiom audit at time of writing: `all_patterns_alive`
and `patternCodes_nodup` depend on no axioms at all; `reconstruct_lexer`
only on Lean's two standard core axioms (`propext`, `Quot.sound`).

Honest scope: shpreflight is a pre-flight *advisor*, not a sandbox. The
Lean proofs cover the lexer's character conservation and the danger
table's integrity — not a claim that every dangerous command is detected.
The pattern table is deliberately small and structural (head + flags +
targets); it is a tripwire, not a policy engine.

## Verify everything

```console
python -m pytest tests -q                                # 55 tests
python -m pytest tests/diff_impls.py -v                  # Python vs Go vs C vs C++ vs Rust CLI parity
go test ./...                                             # Go port
gcc -O2 -std=c99 -DSHPREFLIGHT_NO_MAIN -o c/test_shpreflight.exe c/test_shpreflight.c && c/test_shpreflight.exe   # C port, 455 checks
g++ -O2 -std=c++17 -DSHPREFLIGHT_NO_MAIN -o cpp/test_shpreflight.exe cpp/test_shpreflight.cpp && cpp/test_shpreflight.exe   # C++ port, 455 checks
cargo test --manifest-path rs/Cargo.toml                 # Rust port, 64 tests
powershell -ExecutionPolicy Bypass -File proofs\verify_proofs.ps1
```

Note for building the Rust port on Windows with the GNU toolchain: if
the system MinGW lacks `libgcc_eh`, pass
`$env:RUSTFLAGS = "-C link-self-contained=yes"` — the toolchain ships
the required link libraries itself.
